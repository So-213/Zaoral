# Zaoral フロント/バックエンド分離 移行計画書

- 作成日: 2026-08-11
- 対象: `Zaoral`(このリポジトリ)のみ。`Zaoral_backend2`, `Zaoral_backend3` は対象外。

## 1. 目的

現在Next.js単体(フロントエンド + API Routes + Prisma)で構成されているZaoralを、

- **フロントエンド**: Next.js
- **バックエンド**: Spring Boot

の2つに分離する。

将来的に「AIを用いた新時代の新規開発/リプレイス」の型を作ることも目的の一つであり、
スピード優先ではなく、**ステップとドキュメントを明確にしながら、安全に仕組み化して進める**。

## 2. 前提・方針

- **現行プロジェクトは壊さない**。分離作業は現行プロジェクトのコピー上で行う(コピー作成はステップ2で実施)。
- 移行アプローチは以下の2つを採用する。
  - **仕様の移植**: 現行の挙動・データモデル・APIの仕様を正として、Spring Boot側に移植する。仕様書(このディレクトリ配下)を作りながら進める。
  - **段階的移行**: 一気に切り替えるのではなく、Strangler Fig(絞め殺しの木)パターンで、機能単位・エンドポイント単位で少しずつSpring Boot側に切り替えていく。
- 各ステップの実施内容・調査結果・決定事項は、このディレクトリに番号付きファイルとして残す(下記「4. ドキュメント運用ルール」参照)。

## 4. ドキュメント運用ルール

- このディレクトリ(`docs/移行計画/`)に、ステップごとの番号付きファイルを作成する(例: `01_調査.md`, `02_コピー作成.md`)。
- 各ファイルには最低限「やったこと」「わかったこと・決定事項」「懸念点・持ち越し事項」を書く。
- 本ファイル(`移行計画書.md`)の「3. ステップ一覧」は、ステップの状態が変わるたびに更新する。
- 懸念点で解消しないものは、各ステップファイルの「持ち越し事項」に書き、次ステップへ引き継ぐ。

## 5. 現時点での主要懸念点

- **認証・認可**: NextAuth(v5 beta, JWTセッション)をどう分離するか。フロントに残すか、バックエンドに認可判定を寄せるか([01_調査.md](./01_調査.md)参照)。
- **DB**: Prismaで書かれたスキーマ・マイグレーションをSpring Boot側にどう仕様移植するか。DBを共有し続けるか、段階的に接続元を切り替えるか。
- **AWS(S3)**: 画像アップロード機能(現状一時停止中)の扱い。IAM権限をフロント/バックのどちらに持たせるか。
- **バックエンドの切り分け可否**: 既存API数が4エンドポイントと少なく、service層分離もある程度進んでいるため、分離自体のコストは低いと見立てている。ただし認証まわりの移植方式次第で難易度が変わる。

これらは1つずつ、対応するステップ(4〜7)で結論を出し、ドキュメント化していく。
